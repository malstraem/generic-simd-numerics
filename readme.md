This is prototype of generic linear algebraic objects using current state of
[System.Runtime.Intrinsics](https://learn.microsoft.com/ru-ru/dotnet/api/system.runtime.intrinsics?view=net-10.0) SIMD vectors.

Once was started as try to outperform [Silk.NET](https://github.com/dotnet/Silk.NET), especially on matrix operations with `double` precision.

This stuff is made primarily for in-house engine, but it's possibly helpful draft for https://github.com/dotnet/runtime/issues/24168

### Achieved

- Acceleration for `Vec4<T>`, `Quat<T>`, `Rect<T>` and `Mat44<T>` - operations, various methods and type casts with usefull type combinations
are effectively accelerated (with couple of unnecesary instructions generated by JIT in few places)

- All structs constrainted by `INumber<T>` except of `Quat<T>`

- Unlike `Silk.NET.Maths` and `System.Numerics`, 4x4 matrix have accelerated method
to construct affine transformation from quaternion, scale and translation vectors

- Unlike `Silk.NET.Maths`, rectangle is defined as min+max to effectively accelerate intersects/contains methods

### Not achieved

- Acceleration for `Vec2<T>` and `Vec3<T>` - there is currently no way to efficiently generate load/store operations for structs that do not match the natural register size ([see](./reports/vec2-load-store-comparison.md))

## Benchmarks

> [!NOTE]
check [benchmark reports](./reports) for more results with generated asm and timings</br></br>
tested and benchmarked on AMD Ryzen 9 7900X

All measurements were made using 100k iterations over arrays.
Comparison uses `Mean` and follows `System.Numerics (if float)` -> `our` -> `Silk.NET.Maths` order, `Error` and `StdDev` are omitted.
